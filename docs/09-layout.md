# 09 · 布局与响应式规范

> 组件解决"这一块长什么样"，布局解决"这些块怎么排"。
> 这一层最容易被忽略——组件都对，拼出来的页面照样可以很挤或者很散。

## 1. 页面骨架

三种骨架覆盖全部页面，不要自创。

### 1.1 一级页（Tab 内）

```
安全区顶部
导航栏（大标题 96）
内容区 —— 顶部起始留白 24
  ⋮
内容区 —— 底部留白 ≥ 82 + 安全区底部
悬浮 Tab 栏（高 58，距左右 16，距底部安全区 8）
```

- 底部留白 82 = Tab 栏 58 + 间距 8 + 内容与栏之间 16
- 内容可滚动到 Tab 栏下方，栏是浮在上面的

### 1.2 二级页（有返回）

```
安全区顶部
导航栏（标准 56）
内容区 —— 顶部起始留白 24，底部留白 24 + 安全区底部
```

二级页**不放 Tab 栏**。用户要看主区域就先返回。

### 1.3 弹层页

```
遮罩（页面底色 40% 黑）
面板 —— 顶部圆角 32，底部贴合屏幕，内容区左右内距 16
底部操作区 —— 固定不滚动，高 72 含安全区
```

## 2. 边距与栅格

### 2.1 尺寸类别

| 类别 | 宽度 | 典型设备 | 左右边距 | 列数 | 内容最大宽 |
| --- | --- | --- | --- | --- | --- |
| **Compact** | < 428 | 手机竖屏 | 16 | 1 | 无上限 |
| **Regular** | 428–743 | 手机横屏、折叠屏展开、iPad 分屏 | 20 | 2 | 640 |
| **Expanded** | ≥ 744 | iPad 竖屏 / 横屏 | 24 | 2–3 | 720 |

**内容最大宽**是关键的一条：宽度够大时不是把内容拉满，而是**居中并限制宽度**。
一行文字超过 720 之后阅读效率明显下降，通栏卡片也会显得空。

### 2.2 两列的用法

Regular 及以上才用两列。上两列的条件：

- 两列内容**同等重要**，不要求用户按顺序读
- 每列宽度 ≥ 300
- **同一行的两张卡片高度一致**（不等高会让网格看起来是坏的）

不适合两列的：表单（纵向流程被打断）、时间线、任何需要左右对比的列表。

---

## 3. 纵向节奏

间距只从这一张表里取，不要临时造数字。

| 关系 | 间距 |
| --- | --- |
| 页面顶部 → 第一块内容 | 24 |
| 分组 → 分组 | 24 |
| 区块 → 区块 | 24 |
| 分组标题 → 组内内容 | 8 |
| 卡片 → 卡片 | 12 |
| 卡片内元素之间 | 8 |
| 列表行内元素之间 | 8 |
| 图标 → 文字 | 8 |
| 标题 → 副标题 | 2 |
| 字段 → 说明 / 错误文字 | 4 |
| 输入框 → 下一个输入框 | 16 |

规律：**相关性用间距表达，不靠分割线**。间距 ≤ 8 表示"这是一组"，≥ 24 表示"这是另一块"。

---

## 4. 密度

| 档 | 列表行高 | 卡片内距 | 用在哪 |
| --- | --- | --- | --- |
| **comfortable**（默认） | 60 | 16 | 日常页面、任务列表、设置 |
| **compact** | 44 | 12 | 长列表浏览（全部任务、历史记录） |

规则：

- compact **不让文字变小**，只压缩留白
- compact 下所有可点元素仍须满足 §触控目标（iOS 44 / Android 48），行高 44 时热区就是整行
- 同一屏不混用两档
- 含表单、含破坏性操作的页面**一律用 comfortable**——紧凑会提高误触率

---

## 5. 多设备

### 5.1 手机横屏

- 仍是单列，边距升到 20，内容最大宽 640 居中
- **不要为手机横屏做双列**——横屏高度太小，双列会让每列都放不下一屏内容
- 大标题导航在横屏下自动降级为内联标题（高度不够）

### 5.2 iPad / 平板

- 竖屏与横屏都用 Expanded：边距 24，内容最大宽 720 居中
- 两列时左列放列表、右列放详情（不跳页），这是平板上最自然的用法
- 表单在平板上**仍然单列**，只是居中限宽

### 5.3 折叠屏

- 展开后宽度跨过 600 时，从单列切到两列
- **铰链（Hinge）区域不放任何交互元素**，也不放需要连续阅读的文本
- 折叠状态变化时，滚动位置保持，不要把用户弹回顶部

### 5.4 分屏

按分屏后的**实际宽度**选择尺寸类别，不按设备型号。

## 6. 键盘与安全区

| 项 | 规则 |
| --- | --- |
| 键盘弹出 | 当前聚焦字段必须保持可见；内容整体上移或滚动，不缩放 |
| 底部操作条 | 随键盘上移，紧贴键盘上方；**不叠加安全区** |
| 键盘收起 | 内容回到原位，滚动位置不跳 |
| 安全区顶部 | 导航栏自身承担，内容不重复留白 |
| 安全区底部 | Tab 栏 / 操作条 / Toast 各自承担，只留一次 |
| 底部留白 | 页面底部可滚动区域留 24 + 安全区 |

常见错误：**底部安全区被留了两次**（Tab 栏留一次、内容又留一次），导致页面底部一条宽空白。

---

## 7. 滚动行为

| 行为 | 规则 | 什么时候不用 |
| --- | --- | --- |
| 大标题收缩 | 跟随滚动进度收缩为内联标题 | 标题短、页面本身不足一屏 |
| Tab 栏收缩 | 向下滚动收缩为无标签胶囊，向上立即展开 | 页面不需要滚动 |
| 分组标题吸附 | 分组超过 5 项且需要长距离滚动时 | 分组内少于 5 项——吸附会盖住内容 |
| 滚动到顶部 | 点击状态栏（iOS）/ 点击已选中 Tab | — |
| 加载更多 | 距底部 200 时触发 | 内容总数小于 50 条 |

**滚动容器只有一个**：不要嵌套两层纵向滚动（内层滚动会和外层抢手势）。
横向滚动（如 Chip 行、AssigneePicker）放在纵向列表里是允许的，但要禁用过度回弹。

---

## 8. 列表长度

| 项 | 规则 |
| --- | --- |
| 一屏行数 | comfortable 下 6–8 行 |
| 卡片数量 | 一屏最多 4 张，超过改列表 |
| 超过 50 条 | 分页或虚拟滚动 |
| 超过 200 条 | 必须提供搜索或筛选 |
| 空列表 | 用 `WDEmptyState`，不留空白 |

---

## 9. 验收清单

- [ ] 页面骨架属于 §1 的三种之一，没有自创结构
- [ ] 左右边距按尺寸类别取 16 / 20 / 24
- [ ] 大屏下内容居中且不超过最大宽（640 / 720）
- [ ] 所有纵向间距来自 §3 的表，没有临时数字
- [ ] 分组之间用 24 间距，没有用分割线代替间距
- [ ] 同一屏内密度档位统一
- [ ] 含表单或破坏性操作的页面用 comfortable
- [ ] 两列布局时同行卡片等高
- [ ] 底部安全区只留一次，没有出现双重留白
- [ ] 底部可滚动内容不被 Tab 栏或操作条遮挡
- [ ] 键盘弹出时聚焦字段可见，操作条上移且不叠加安全区
- [ ] 只有一个纵向滚动容器，没有嵌套
- [ ] 分组少于 5 项时没有用吸附标题
- [ ] 折叠屏铰链区域没有交互元素
- [ ] 横竖屏切换、分屏后滚动位置保持
- [ ] 空列表都有空状态，没有留白
