## 0. 本轮怎么做的

第一轮（§10）是"查账"：设计方自查 + 三方互评。本轮换了方法 —— **先立一份可复算的证据基线，再让三方各自背书，最后用不采信任何一方的独立核验去打。**

| 环节 | 执行 | 产出 |
| --- | --- | --- |
| 队长前置核验 | 三仓 git 状态、令牌逐一解析、`build.js --check`、源码取证 | 基线快照：`iOS 316b75f` / `android 524f5d6` / `wisdomdesign e495147` |
| 三方独立复核 | 架构师 / 设计师 / 研发Leader 各写一份，**互相不可见** | `12-review-architect.md` / `13-review-designer.md` / `14-review-techlead-round2.md` |

### 1.3 架构级结论：能承载令牌消费，不能承载组件 API 契约

两端各只有 3 个手写 Foundation 源文件、**零组件、零 CI、零 lint、零截图基线**。决定返工量的不是组件数量，而是 **8 个"现在不定就 37×2 次返工"的形态**：

**iOS**：I1 `WDTextStyle` 最终字段集（缩放策略 + 行高比 + `letterSpacing` + 字族槽位）／I2 控件尺寸缩放形态（`@ScaledMetric` 进不了 enum 静态常量）／I3 **主题注入点缺失**（`grep EnvironmentKey\|EnvironmentValues iOS/Sources` → 空，而 Android 有 `CompositionLocal`）／I4 组件外观暴露方式。

**Android**：A1 M3 角色映射清单（只 10 个）／A2 主题是否提供 typography/shapes／A3 动态取色开关与 `WDColors` 可构造性（`wdLightColors` 是 `internal`）／A4 视觉尺寸与命中尺寸命名分家。

**两端共性**：文案注入形态必须在 Foundation 落地（它是公开 API 签名的一部分）；`component.*` 一次给全；**生成器对称性**（iOS 生成 `elevation`、Android 完全不生成；`material.*` 与 `motion.component.*` 两端都不生成）。

> 全文见 [`13-review-designer.md`](13-review-designer.md)。发言要点：**设计方向站得住，设计稿没兑现。**

### 2.1 一句话诊断

### 2.2 必须带进结论的五件事

#### ① 色晕净 alpha 必须先定（D1 / D16）

第一轮"66% → 42%"隐含"仍乘预览的 `opacity:.55`"，但这个口径**从未写进令牌**。两种读法差一档：

| 读法 | 合成色（湖水蓝 on canvas） | 相对亮度 |
| --- | --- | --- |
| 直接 42% | `#D6E9EF` | **0.788（最深）** |
| 42% × `.55` | `#E2F0F4` | 0.850（最浅） |
| 旧 66% × `.55` | `#D9EBF0` | 0.805 |

**删掉 `.55` 而只写 42%，结果比现状更浓** —— 与用户三次"再浅一点"的方向相反。裁决：令牌直接写**生效 alpha 23 / 16 / 6%**，删 `preview:1423` 的 `.55` 与 `:1468` 的 `.5`。

> **交叉复核订正（`13-review-designer-peer.md`）**：该组数字**复算不出同值** —— 独立按真实径向渐变几何（601×601）像素采样得等效 α **27.4 / 18.6 / 14.8%**，换成 42% 后为 **17.5 / 13.4 / 14.8%**。**结论方向成立（必须写"生效 alpha"），具体换算值以 M0 断言产出为准，不采用 23/16/6。**

#### ② 深色端是 M0 硬阻塞（D3 / D4 / D15）

浅色卡叠深底色晕 → `text.tertiary` 2.40、`text.secondary` **3.42**。**B10 只带了 tertiary，secondary 漏了**。且复算证明**降浓救不了深色端**：tertiary 要 4.5 需 α≤14%，那时色晕等于不可见 → 只能换派生源（`#123449` 36% → 13.84 / 8.05 / 5.66 达标）。A2「压向青灰」缺可断言口径：深色表面族 5 个令牌无一取自 su 阶（色相 205–208° vs su 200–203°）。

> **交叉复核订正**：D3"降浓在数学上救不了"**不成立**（tertiary 达标只需 α≤14.2%，与"换源"是两条都可行的路，不是唯一解）；`ΔL` 由 0.006 复算为 **0.0226**；按真实几何独立采样得 tertiary **2.84** / secondary **4.03**（与设计师的 2.40 / 3.42 不同）。**结论（深色端当前不达标、必须与浅色端同批修）成立，具体数值待断言统一产出。**

#### ③ tint 配方给死了（D6 / §5.1）

品牌蓝 `#1677B3` **16% over `surface.card`** → `#D9E9F3`，反解自亮度阶梯 0.80。设计稿 `#D5EBF6` 属品牌蓝族（色相 200°）不是湖水蓝族（191°）。**且 `gradient.surface` 被当组件填充用共 5 处**，第一轮只裁定了 tonal 2 处 → **Chip 已选（`specs/01-basic:956`）与 Badge shared（`:1050`）是同一缺陷未修**。

#### ④ 设计师明确不同意第一轮的一处（§5.2）

Tab 栏未选标签（11pt + `text.tertiary`，`specs/02-advanced:1390/1375`）**不该只"把 tertiary 数值修达标"，应改 `text.secondary`** —— 导航标签是必需信息，不该把最低对比度文字放在最不稳的玻璃底上。

> **交叉复核**：该立场与 `11-conclusions.md:77`（Tab 字号决议）**直接冲突**（K1）；撤回群青是**新决议**（K2）。需产品/设计当轮裁定。

#### ⑤ A1 中文字体的设计后果（§5.3）

设计侧**服从产品裁定**，但形态 = **组件库零字体 + 产品层增强包**；必须同批冻结 4 件：`family.cjk` 令牌、字重缺档回落表、CJK 行高比、数值继续走西文字族。否则 M1 的 `WDTextStyle` 会**在没有中文约束的数值上冻结**。

> **交叉复核**：A1 冲突成立 —— §5.3 与第一轮 S6（`10:1145`）同义，而 `11:30` 明写覆盖该建议 → **A1 在库侧零落点**；`family.cjk` + 宿主注入是 `11:85` **未列入的新增令牌 / 公开 API**。

### 2.3 设计侧必须补的规格（除上述四项外）

## 5. 队长复算：改口径的四条

以下四条是本轮**独立于三方意见、由队长在汇总时复算得出**的新结论，它们把第一轮的结论口径改了：

### 5.1 `text.tertiary = #4C616D` 在浅色色晕上**不达标**（第一轮最严口径算错了方向）

第一轮说该值"最严口径 4.61"。按浅色色晕三色标 **42%** 合到 `bg.canvas #F1F8FA` 复算：

| 文字 | canvas | 湖水蓝 42% | 天青 42% | **群青 42%（最不利）** |
| --- | --- | --- | --- | --- |
| `#4C616D`（决议值） | 6.04 | 5.18 | 4.73 | **3.80 ❌** |
| `#5B7784`（现状） | 4.43 | 3.79 | 3.47 | 2.79 ❌ |
| `#3E5764`（secondary） | 7.10 | 6.09 | 5.56 | 4.47 ⚠️ |

**问题在于方向**：色晕把底色**压暗**（群青 42% 后 L=0.565，canvas L=0.927），而 tertiary 是**深色文字** —— 深字配暗底时对比度**下降**，所以最不利背景是**最暗的那个色标**，不是最亮的。"4.61" 对应的是比 canvas 更亮的底（L≈0.77），而浅色色晕里没有任何色标比 canvas 更亮。**结论：`#4C616D` 在色晕上不达标（3.80），第一轮的"已裁定"实际未收口；M0 必须靠断言算法给出首个达标值，不能在文档里先定数。**

### 5.2 深色玻璃有**四个**来源，不是一个

| 来源 | 值 | 备注 |
| --- | --- | --- |
| `semantic.dark.surface.glass` | `#0A1A288C` | 平台实际实现的那个（RGB `0A1A28`） |
| `material.regular.fillDark` | `#0C20389E` | **另一套 RGB**（`0C2038`），生成器不读（B11） |
| `01-foundation §7.2` 正文 | "导航 62% / Tab 62% / 浮层 82%" | 第三套 |
| 画廊产物 | `--g-glass .70/.55`、`--g-glass-strong .88/.78` | **第四套**；且配方画廊的 `--g-glass` 取的是 `glass-strong` 的值（V4） |

第一轮 §3.2 裁定"玻璃取值以 `material.*` 令牌为准"，但**平台上跑的是另一套**；`--g-scrim` 甚至**有产物、无令牌**（V6）。→ **玻璃与色晕的真源裁定是 M0 的第一件事，且必须先于任何断言工作。**
