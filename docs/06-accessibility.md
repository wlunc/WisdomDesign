# 06 · 无障碍规范

> 这份文档是**验收的硬门槛**。组件规格里的每一条"无障碍"章节都引用本文；
> 本文没过的组件，不进入 M2 之后的任何一个里程碑。

## 1. 为什么这一层要求特别严

三个人群决定了它必须是硬门槛，而不是"尽量做到"：

| 人群 | 场景 | 受影响的功能 |
| --- | --- | --- |
| 老人 | 老花、手抖、看不清浅色 | 字号、对比度、触控热区、按钮间距 |
| 孩子 | 认字不全、误触 | 图标必须有文字、破坏性操作要有确认 |
| 视障用户 | 读屏操作 | 标签、角色、焦点顺序、自定义操作 |

家庭工具的用户天然包含这三类人，所以这里不做"最小可用"，直接按验收项执行。

---

## 2. 四条底线

任何组件违反了这四条，直接判不通过，不看其他项。

| # | 底线 | 判定 |
| --- | --- | --- |
| 1 | 触控目标 ≥ **iOS 44pt / Android 48dp** | 实测热区，不是视觉尺寸 |
| 2 | 正文与背景对比度 ≥ **4.5:1**；图形与边界 ≥ **3:1** | 用取色器实测 |
| 3 | 状态**不只靠颜色**表达 | 同时有形状、文字或字重变化 |
| 4 | 动态字体放大到 **AX3 / fontScale 1.3** 不截断、不重叠 | 真机或模拟器实测 |

> 组件规格里写的「≥ 44」指的是 **iOS 的下限**。Android 按平台规范执行 **48dp**，
> 两端各自达标即可，不要求数值相同。

---

## 3. 屏幕阅读器

### 3.1 标签写法

三条规则，按优先级：

1. **写动作，不写图标名**：写"搜索"不写"放大镜"；写"删除任务"不写"垃圾桶"
2. **补上下文**：同一个页面上有多个"删除"时，标签要写清删的是什么——"删除整理储物间"
3. **数字给单位与总量**："已完成 3 项，共 5 项"不写"3/5"

### 3.2 常用句式模板

照抄这些句式，不要自己造。

| 场景 | 朗读文本 |
| --- | --- |
| 普通按钮 | `保存` |
| 图标按钮 | `搜索` / `关闭新建任务` |
| 加载中的按钮 | `保存，处理中` |
| 禁用元素 | `保存，不可用` |
| 复选框 | `买牛奶，未选中，复选框` |
| 任务行复选框 | `整理储物间，未完成，复选框` |
| 单选组内一项 | `仅自己可见，已选中，单选按钮，第 1 项，共 2 项` |
| 开关 | `共享给家人，开，开关` |
| 滑块 | `完成度，62%，可调整` |
| 步进器 | `数量，3，可调整` |
| 进度条 | `上传进度，45%` |
| 环形进度 | `本周家务，已完成 3 项，共 5 项，60%` |
| 输入框 | `任务名称，编辑框`；错误时 `任务名称，错误，名称已被占用` |
| 列表行 | `整理储物间，18:00 前，未完成，按钮` |
| 头像 | `妈妈，在线` |
| 头像堆叠 | `家庭成员 6 人：我、妈妈、爸爸、妹妹，另有 2 人` |
| 导航栏返回 | `返回家庭列表` |
| 标签栏一项 | `今天，已选中，第 1 项，共 4 项` |
| 状态徽标 | 并入宿主：`提醒，3 条未读` |

### 3.3 角色映射

| 组件 | iOS trait | Compose role |
| --- | --- | --- |
| Button | `.isButton` | `Role.Button` |
| IconButton | `.isButton` | `Role.Button` |
| Checkbox | `.isButton` + 值"已选中/未选中" | `Role.Checkbox` |
| Switch | `.isButton` + 值"开/关" | `Role.Switch` |
| Radio | `.isSelected`（组内） | `Role.RadioButton` |
| Slider | `.isAdjustable` | `Role.Slider` |
| 分组标题 | `.isHeader` | `heading()` |
| 可点卡片 | `.isButton` | `Role.Button` |
| 展示型徽标 / 分割线 / 骨架 | 不进入无障碍树 | `clearAndSetSemantics {}` |

### 3.4 焦点顺序

- 按**视觉阅读顺序**：从上到下、从左到右
- 列表整行作为一个焦点，不把行内每个元素单独暴露——否则读一条任务要按四五次
- 弹层出现时焦点**进入弹层并限制在内**；关闭后**归还到触发元素**
- 视觉上浮在最上层的元素（FAB、Toast）**不抢焦点**，逻辑顺序仍在内容之后
- 装饰性元素（分割线、图标底座、渐变）不进入树

### 3.5 播报时机

| 事件 | 播报方式 | 频率 |
| --- | --- | --- |
| 页面加载完成 | 首个焦点自动朗读 | 一次 |
| 操作成功 | `polite` | 一次 |
| 操作失败 | `assertive` / `alert` | 一次 |
| 进度变化 | 只在跨过 25% / 50% / 75% / 100% 时 | 最多 4 次 |
| 搜索结果数量变化 | `polite`，读"找到 3 项" | 每次结果变化一次 |
| 拖动滑块 / 输入文字 | **不播报** | 松手后才播报一次 |
| 骨架加载中 | `polite`，整个骨架区读一次"加载中" | 一次 |

**绝不能每个动画帧都播报**。这是读屏体验变差的第一大原因。

## 4. 动态字体

### 4.1 断点

| 档位 | iOS（约） | Android（fontScale） |
| --- | --- | --- |
| 默认 | 100% | 1.0 |
| 放大一档 | 115% | 1.15 |
| 验收上界 | **AX3（约 175%）** | **1.3** |

组件必须在验收上界下不截断、不重叠。规格里没特别说明的，按此执行。

### 4.2 跟着放大 vs 锁死

| 元素 | 行为 | 原因 |
| --- | --- | --- |
| 所有文字 | **跟着放大**，容器高度同步增高 | 这是动态字体的意义 |
| 图标 | **锁死尺寸** | 图标放大不增加信息量，只会挤掉文字 |
| 头像 | **锁死直径** | 同上，且会破坏堆叠计算 |
| 复选框 / 单选框 | **锁死 26** | 形状本身是信息，放大反而怪 |
| 进度环 | **锁死直径**，环内数字放大 | 数字是信息，环是容器 |
| 行高 | **同步增高** | 不裁切的前提 |

### 4.3 一行放不下时的降级

文字放大到放不下时，按这个顺序降级，**不允许截断**：

1. 左右排布 → 改成上下排布（`WDFormRow`）
2. 一行两个控件 → 改成一行一个
3. 横向排列的按钮 → 改成纵向堆叠，主操作在上
4. 标签栏文字 → 允许 2 行，超过则只留图标 + 无障碍标签
5. 徽标与宿主同行 → 徽标换行到宿主下方

## 5. 对比度

### 5.1 验收表

| 内容 | 下限 | 我们的实际值 |
| --- | --- | --- |
| 正文（< 18.66pt 粗体 / < 24pt） | 4.5:1 | 浅色 canvas 上 `text.primary` 16.3:1；`text.secondary` 7.1:1；`text.tertiary` 6.0:1（色晕最暗处 5.5:1） |
| 大字号（≥ 18.66pt 粗体） | 3:1 | `type.largeTitle` 等远超 |
| 图形、图标、控件边界 | 3:1 | 填充与轨道 3:1 以上 |
| 禁用态 | 不适用（可辨识即可） | 40% 不透明度 |
| 焦点光环 | 3:1（对相邻色） | `text.brand` 18–32% 叠加 |

### 5.2 玻璃层上的文字

玻璃会随下方内容变色，所以**能放什么字由玻璃档位决定**。下表按最不利口径实算（浅色端取最暗内容、深色端取最亮内容），完整推导见 [`12-b22-glass.md`](12-b22-glass.md) §4：

| 玻璃档 | `text.primary` | `text.secondary` | `text.tertiary` |
| --- | --- | --- | --- |
| 浅色 `surface.glass`（70.2%） | 8.4:1 ✅ | **3.6:1 ❌** | **3.1:1 ❌** |
| 浅色 `surface.glass-strong`（85.9%） | 12.7:1 ✅ | 5.5:1 ✅ | 4.7:1 ✅ |
| 深色 `surface.glass`（62.0%） | **4.1:1 ❌** | 2.4:1 ❌ | 1.7:1 ❌ |
| 深色 `surface.glass-strong`（78.0%） | 7.2:1 ✅ | **4.2:1 ❌** | **2.9:1 ❌** |

规则：

1. **浅色端** `surface.glass` **只放 `text.primary`**；`secondary` / `tertiary` 必须改用 `glass-strong`，否则不上玻璃。
2. **深色端**任何字阶都**不上 `surface.glass`**；`glass-strong` **只放 `text.primary`**。
3. **悬浮 Tab 栏用 `glass-strong`**；深色端的 Tab 栏改用不透明表面（`surface.card-solid` + 顶部高光 + 外圈细线），未选标签才能用 `text.secondary`。
4. **语义色（`status.*`）不上玻璃** —— 只在软底或实底上使用。
5. 下方是照片或高饱和内容时，文字下垫一层 25% 不透明度的 `surface.card-solid`。
6. 验收时**取最不利位置的背景色**测对比度，不是取平均；玻璃一律取"最暗内容"或"最亮内容"的合成色。

## 6. 动效与减弱动态效果

系统开启「减弱动态效果」后，按此表降级：

| 常态 | 降级后 |
| --- | --- |
| 弹簧动画 | 线性，150ms |
| 位移与缩放 | 交叉淡入淡出 |
| 骨架微光 | 停止，显示静态灰块 |
| 玻璃高光扫过 | 停止 |
| 进度环旋转 | 停止，显示静态进度 |
| 下拉刷新的旋转环 | 改为静态环 |
| 页面转场 | 直接切换，无滑动 |

实现上不要自己判断，读系统设置：

- iOS：`@Environment(\.accessibilityReduceMotion)`
- Android：系统的动画缩放设置（Compose 的 `LocalMotionDurationScale`）

同时支持 **降低透明度**（`accessibilityReduceTransparency`）：开启后玻璃降级为不透明表面。

## 7. 触觉

| 事件 | iOS | Android |
| --- | --- | --- |
| 按钮按下 | `UIImpactFeedbackGenerator(.light)` | `TextHandleMove` |
| 勾选 / 开关切换 | `.light` | `TextHandleMove` |
| 步进 / 到达滑块端点 | `.rigid` | `LongPress` |
| 下拉刷新到阈值 | `.medium`，**只触发一次** | `LongPress` |
| 完成一个任务 | `.light` + 视觉回弹 | 同左 |
| 危险操作确认 | `.warning` | `LongPress` |

规则：**同一次操作只给一次触觉**。连续步进、拖动滑块这类高频动作不要每次都给。

---

## 8. 不依赖颜色的状态

我们的语义色是柔和版（柔和红、蜂蜜黄），色盲用户更难区分，所以**每个状态必须配形状不同的图标**：

| 状态 | 颜色 | 图标（形状必须不同） |
| --- | --- | --- |
| 成功 | `status.success` | 对勾 `check-circle` |
| 信息 | `status.info` | 圆圈 i `info` |
| 警示 | `status.warning` | **三角形** `alert-triangle` |
| 错误 | `status.danger` | **实心禁止** `x-circle`（且文案加粗） |

同一原则适用于：

- 选中态：颜色 + 字重 + 形状（勾 / 圆点 / 描边环）三者至少两个
- 在线状态：有圆点 = 在线，**没有圆点 = 离线**（不要用灰点表示离线）
- 进度：颜色 + 长度/角度

## 9. 输入方式

| 方式 | 要求 |
| --- | --- |
| 键盘（外接） | 所有可点元素可 `Tab` 到达；焦点光环可见；`Esc` 等价于返回/取消；`方向键` 在分段控件、单选组、滑块内移动 |
| 开关控制（iOS） | 不依赖多点手势；左滑删除必须同时提供自定义操作或按钮 |
| 语音控制 | 元素的可访问名称必须唯一且可读，避免页面里出现 8 个都叫"删除"的按钮 |
| 手势 | 任何手势都必须有等效的非手势入口（左滑删除 ↔ 自定义操作；下拉刷新 ↔ 刷新按钮） |

## 10. 组件级验收清单

每个组件交付前逐条过，全部勾上才通过：

- [ ] 触控热区达标（iOS ≥ 44pt / Android ≥ 48dp），实测而非目测
- [ ] 所有可点元素都有无障碍标签，且标签写动作不写图标名
- [ ] 同页面内同功能的标签可区分（不出现两个一样的"删除"）
- [ ] 角色映射与本文 §3.3 一致
- [ ] 列表行、卡片这类复合元素合并为单个焦点
- [ ] 弹层焦点进入并限制，关闭后归还触发元素
- [ ] 动态字体放大到 AX3 / 1.3 不截断、不重叠、不裁切
- [ ] 按 §4.3 的顺序正确降级，没有出现截断
- [ ] 文字对比度 ≥ 4.5:1（玻璃上取最不利位置实测）
- [ ] 图形与边界对比度 ≥ 3:1
- [ ] 状态不只靠颜色，图标形状有区分
- [ ] 减弱动态效果开启后按 §6 降级
- [ ] 降低透明度开启后玻璃降级为不透明
- [ ] 触觉符合 §7，且同一次操作只给一次
- [ ] 手势都有等效的非手势入口
- [ ] 深浅两种外观都验证过，浅色优先

## 11. 怎么验

| 项 | 方法 |
| --- | --- |
| 对比度 | 设计稿取色后用对比度工具实测；玻璃上取最不利位置的合成色 |
| 动态字体 | 模拟器把字号调到 AX3 / fontScale 1.3，逐屏截图比对 |
| 读屏 | iOS 开 VoiceOver 全流程走一遍（不看不点，只听）；Android 用 TalkBack |
| 焦点顺序 | 用外接键盘 `Tab` 走一遍，确认顺序与视觉一致 |
| 触控热区 | iOS 用 Accessibility Inspector；Android 用布局边界检查 |
| 减弱动态效果 | 系统设置里开启后重走一遍动效相关流程 |

**读屏验收必须闭眼做**：看着屏幕操作会下意识补全信息，测不出标签缺失。
