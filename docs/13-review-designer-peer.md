## 2. 设计与产品裁定的冲突检查

被复核对象是 `docs/11-conclusions.md` §1 的两条产品裁定。以下逐条给**冲突语句 + 对应裁定条目 + 后果**。

### 2.1 A1 中文字体：裁定「采用嵌入」 vs 设计侧「组件库零字体」

**裁定原文（E1）**

- `11:30`：**A1 中文字体｜采用嵌入（覆盖设计侧"不嵌入"建议；落地细节见 §5 开放项）**
- `11:122`（§3.6 建议项状态表）：**S6 中文字体不嵌入 → 被 A1 覆盖 → 改为嵌入**
- `11:185`（§5 真开放 1）：嵌入"哪一套"、是否子集化、授权，以及 **9MB+ 体积由组件库还是产品层承担**

**设计侧立场原文（E1）**

- §5.3：「**组件库零字体；"嵌入"落在产品层的品牌增强包。** 组件库只提供**字族令牌 + 降级链 + 字重回落表**；中文字体文件由产品 App 引入，库通过 `typography.family.cjk` 接收宿主注入的字族名。」
- §5.3 理由 3：「架构师 `10:1145` 给的"组件库零字体 + 产品层可选增强"是可执行形态，**设计侧同意**；差异只在于：我把"产品层嵌入"设为**默认推荐**。」
- §7.3：「设计侧主张"组件库零字体 + 产品层增强包"…**裁定的是"要不要"，我补的是"谁付体积"**。」

**结论：冲突成立（实质冲突，非纯补充）。** 三点判定依据：

1. **形态同源**：`10:1145` 的 S6 原文是"组件库零字体 + 产品层可选增强"，A1 明确写了覆盖 S6。设计侧 §5.3 的形态与 S6 逐条同义（库零字体 / 产品层承载 / 库只给令牌与回落）。把"库零字体"称为"补充谁付体积"，与 A1 的覆盖语句**字面相反**。
2. **落点缺失**：在该形态下，M0 的 A1 交付物**不含任何中文字体文件**，即"采用嵌入"在组件库范围内没有任何落点，全部依赖一个**不在本次评审范围内**的产品层包（本轮产物只有组件库 + 预览 + 画廊，见被复核稿 §1.1 的范围表）。
3. **越权定夺待定项**：`11:185` 把"体积由组件库还是产品层承担"列为**真开放问题**（需产品/用户）。设计侧 §5.3 单方面定为产品层并称"默认推荐"，绕过了该开放项的定夺主体。

**后果（若不修订）**

- 第二轮讨论稿会把 A1 写成"已按设计侧形态落地"，而库侧实际零交付 → M1 的 `WDTextStyle` 冻结（`11:109`）会在一套**没有中文字体约束来源**的令牌上完成。
- `typography.family.cjk` + 宿主注入是**新增令牌 + 新增公共 API**，不在 `11:85`（新增令牌清单）与 `11:109`（M0 冻结口径）之内；若采纳，M0 的令牌变更范围、`apiDump` 与两端 lint（`11:173`）都要跟着扩。
- 若产品/用户最终判定体积归组件库（与设计侧推荐相反），§5.3 的三条理由（授权、跨端发布风险、库被别的 App 引入）全部要重写。

**不冲突的部分（应保留）**：§5.3 的"四条设计后果"（字族令牌要能表达中文/西文两套、字重缺档回落、CJK 行高比、数值继续走西文字族）确实是 A1 的落地缺口，且不与裁定冲突；其中"数值一律走 `family.sans`"是**新增约束**，需并入 M0 一并冻结。

- **后果**：这些声明在计算值阶段失效（invalid at computed-value time）→ 画廊的标题/说明/组件编号/分层徽标的文字色与底色**不来自任何令牌**，而是继承宿主页面默认值；`.spec-tier` 的 `background:var(--wd-card)` 与 `border:1px solid var(--wd-border)` 同样失效。**在画廊里做设计评审时，被评审的是"没上色的文字"**。
- **为什么属设计侧**：画廊是设计侧的评审产物（`05:12`"规格画廊｜设计·产品｜静态 HTML｜浏览器可直接审"）。
- **被复核稿为何漏**：它只看了 `--g-*`（D2/D16）与 `--wd-*`（D2/D7/D8），没做"定义 vs 引用"的差集。

### D-M2 · `01-foundation.md:151-156` **已有完整的三档色晕配方与几何**，D1 的关键证据不成立【E1 · 高】

## 4. 结论

### 4.1 该文档能否作为第二轮讨论稿的设计侧输入

**结论：需修订（needs revision）。** 修订后可作为第二轮讨论稿的设计侧输入；在修订完成前**不宜**直接并入汇总稿，理由：

- **可以采信的**（我逐条独立复核后确认）：§2.2 十三行落地表（逐行成立）；"深色端当前不达标"（我的采样值更硬）；"tint 属品牌蓝族"的反解；"RTL 四份设计稿 0 覆盖"；"四份 HTML 不在生成链路"；D4/D5/D9/D10/D11/D12/D14/D16 的事实部分；§3.1/§3.2/§3.6 的方向判断。
- **不可直接采信的**：D1 的关键证据（规范里有配方）、D3 的两个量化论据（α 上界与 ΔL）、§6.3 的排期算术、D13 的字体分类、D15/D17 的"不合规/会跳色"后果、§1.4 的文件计数、以及 §2.1 与 A1 的冲突表述。
- **不能被它替代的**：本轮 12 条遗漏项（D-M1…D-M12）里，D-M1/D-M2/D-M3/D-M7/D-M10 会直接改变 M0 的交付范围或修订方式。

### 4.2 必须修订项清单（按优先级）

**A 类 · 不改会误导第二轮裁定（5 项）**

1. **§2.1 D1 的证据改写**：删除"`01:149` 只是 18–66% 区间、不是三档配方"；改为"`01:151-156` 已有完整三档配方与几何（与 `preview:1380-1383` 一致），需修订的是 `11:65` 的 42% 与该配方的生效口径关系"。同时把"wash 令牌不存在"改为"决议已要求新增（`11:85`），尚未落地"（C2）。
2. **§2.2/D3 的量化改写**：①把"降浓在数学上救不了"改为"降浓可让 tertiary 达标（α ≤ 14.2%），但此时色晕与底色的对比只剩 1.38:1，属设计不可接受——这是政策判定而非数学不可能"；②删除"α=14% 时亮度差约 0.006"（我算 ΔL≈0.0226）；③给 2.40/3.42 标注"色标名义峰值（中心在可视区外）"，并补真实几何采样的最不利值（我的：`#3D5461` → tertiary 2.84 / secondary 4.03）。
3. **§5.3 与 A1 的关系改写**：明写"§5.3 的形态 = S6（库零字体）的复述"，并二选一：要么承认这是对 `11:30`"采用嵌入"的**重新提案**（交产品/用户重裁），要么按 A1 给出库侧最小落地（字族令牌 + 降级链 + 字重回落）并**保留 `11:185` 的体积归属为待定**。同时把 `typography.family.cjk` 与宿主注入列为"新增令牌 + 公共 API"，补进 M0 范围影响清单。
4. **D15 与 A2 的关系改写**：把"统一取 200–203°"标注为**设计侧建议口径（待三方/用户采纳）**，与 `11:31`/`11:66`/`11:186` 的"可以 + 目标色值待定"分栏；消解自相矛盾（其推荐的深色色晕源 `#0F4055` 色相 198.0°，落在自己给的带外）；把"200–203°"与"与 su.900 相差 ≤3°"两个口径并为一个。
5. **§6.3 的算术**：表内自加为 **6.0 天**（不是 6.5），"第一轮 6 天"应改为 `10:433` 的 **5.5 天**口径；里程碑不动这个结论可保留。

**B 类 · 事实与引用修正（4 项）**

6. 行号与计数修正：`--wd-grad-deep` → `preview:1346`；`ACCENTS.deep.fill` → `preview:2081`；D16"唯一的 `radial-gradient`" → "每份画廊 2 处（`:612` 点阵、`:982` 单选圆点），均非页面色晕"；§1.4 的 iOS"5 个 Swift 文件" → "4 个 `.swift` + `Package.swift`"；D9 的"全部文档里只出现这一次" → "现行规格/架构文档里"；§3.5 的 RTL 计数给出统计口径（不重复声明 **61** 处，含 `text-align` 62 处；其"62 + 另有 8 处"为重复计数）；文档层方向词给出词表（我按"左右/左对齐/左侧/左滑/左列"得 **63** 处）。
7. 把摘要的"只有 1 条真正落地"与 §2.2 第 13 行"半兑现"统一为"**12 未落地 + 1 半落地 + 0 完全落地**"（C1）。
8. 补 D2 的令牌内部两套深色玻璃（D-M7）；补 D14 的预览 `.94` ≠ 94.12%（D-M8）。
9. §5.2 的 Tab 一条改措辞：从"该条我不同意第一轮的处理"升级为"**与 `11:77` 的 Tab 字号决议直接冲突**"，并说明这是改决议而非修数值。

**C 类 · 建议补入的遗漏项（可放附录或就地扩写）**

10. D-M1（画廊引用未定义 `--wd-*`）→ 影响 D16 的修订方案：生成链路必须覆盖画廊骨架色，否则"进生成链路"只解决 `--g-*`。

### 4.3 给队长的一句话

设计侧的**结论**基本可以用；但它的**证据层**有 4 处硬错（1 条把"规范缺失"说错、1 条把"数学不可能"说错、1 处排期算术、1 处字体外部事实）和 1 处与产品裁定的实质冲突（A1）。建议在第二轮讨论稿里：**采纳其结论、替换其证据、并把 A1 的分歧挂回产品/用户**。
