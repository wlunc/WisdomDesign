## 0. 一句话

三条欠账的共同点是**缺的不是想法，是能算的数**。这一版给的是能直接进实现的数：

- **A-11** 成员四色是**一套单调递减的明度阶梯**（不是四个随机好看的颜色），首字色按 tone 配对，分配按**成员 ID 哈希**（`member.id` 的 FNV-1a mod 4）—— 这两个决定合起来才满足「同一个人在任何页面配色一致」。
- **A-13** `media` 的图片带 = **通栏 + 16:9 + 最小高 96**，图片不叠卡片内边距（这是圆角处「不出重影」的唯一画法），文字区仍走 16。
- **A-14** 长按提示是 **500ms 阈值 + 28 高气泡 + 达到阈值即取消点击**；它**不替代**无障碍标签，只作「图标含义模糊」时的补充。

## 1. A-11 · 成员配色与照片形态

### 1.1 结论先行（是 / 否）

| # | 问题 | 结论 |
| --- | --- | --- |
| **C1** | 四色放进 `semantic` 成为 33–36 号槽位吗？ | **不。** U12 槽位冻结在 **32**，加槽 = 二次 breaking。新增独立组 `member.{light,dark}.tone-N`，与 `material` / `gradient` 同处理 |
| **C2** | 四色是四个好看的颜色，还是一条阶梯？ | **一条阶梯。** 相对亮度严格单调递减，相邻 ΔL ≥ 0.05；生成器 `assertMemberTones()` 逐套断言 |
| **C3** | 首字色统一用一个吗？ | **不。** 一个色值撑不住四档：深字 `#0A1B24` 在浅色 tone-3 / tone-4 上只有 **3.69 / 2.08**（白字则 4.77 / 8.43）；反过来白字在 tone-1 / tone-2 上只有 1.5 左右。每 tone 配一个 `ink`，八组全部 ≥ 4.5:1 |
| **C4** | 怎么保证同一个人换页不换色？ | **按成员 ID 哈希**：`FNV1a32(memberID) mod 4`。不用数组下标、不用出现顺序、不用名字首字 |
| **C5** | 照片形态要不要新参数？ | **要。** 新增 `WDAvatarImage` 值形态（`init(image:)`）；照片缺失**必须能退回文字形态**，回退内容由调用方给，库内不猜 |
| **C6** | 空图 / 加载中显示破图吗？ | **不。** 没有可渲染内容时**退回落色文字头像**；禁止破图、禁止灰框占位 |
| **C7** | 深色端四色和浅色端是同一组值吗？ | **不是，但同族。** 深色端整体抬亮（深底上要 ≥ 3:1 才看得见头像边界）；逐档色相差 = **0.8° / 0.3° / 0.3° / 7.8°**（第 4 档为拿到白字对比度略偏靛） |

### 1.2 四色取值

**浅色外观**（`member.light`）

| tone | fill | L | ink | ink 对比度 | 档位 |
| --- | --- | --- | --- | --- | --- |
| `tone-1` | `#B0D5DF` 湖水蓝 | 0.621 | `#0A1B24` | **11.24:1** | 最亮 |
| `tone-2` | `#7EC4CF` 天青 | 0.484 | `#0A1B24` | **8.94:1** | 次亮 |
| `tone-3` | `#1A7BA3` 石青 | 0.170 | `#FFFFFF` | **4.77:1** | 次深 |
| `tone-4` | `#065279` 靛蓝 | 0.075 | `#FFFFFF` | **8.43:1** | 最深 |

相邻 ΔL = **0.137 / 0.314 / 0.095**。

**深色外观**（`member.dark`）

| tone | fill | L | ink | ink 对比度 | 对 `bg.canvas` |
| --- | --- | --- | --- | --- | --- |
| `tone-1` | `#97CBD8` | 0.542 | `#0A1B24` | **9.91:1** | 9.89:1 |
| `tone-2` | `#6BBBC7` | 0.428 | `#0A1B24` | **8.00:1** | 7.98:1 |
| `tone-3` | `#4193B4` | 0.253 | `#0A1B24` | **5.07:1** | 5.06:1 |
| `tone-4` | `#356997` | 0.131 | `#FFFFFF` | **5.80:1** | 3.02:1 |

相邻 ΔL = **0.114 / 0.175 / 0.122**。与浅色端逐档色相差 = 0.8° / 0.3° / 0.3° / 7.8°。

三条设计取舍：

1. **深色端整体比浅色端亮。** 深色 `bg.canvas` 的 L 只有 0.010，照搬浅色端取值会沉进背景。深色端四档抬到 0.542 / 0.428 / 0.253 / 0.131，最暗档仍有 3.02:1（图形边界下限）。
2. **浅色端 tone-1 / tone-2 与定稿色卡的 lake / mist 同值**（`#B0D5DF` / `#7EC4CF`）。画廊的既有观感不变，只把「4 组硬编码渐变」换成令牌。
3. **不用渐变。** 画廊里的 `linear-gradient(135deg,…)` 是网页装饰，令牌层给**平色**：① 首字对比度必须对一个确定值算，渐变最不利端与设计档位会打架；② 头像最小 20pt，渐变在这个尺寸上看不出，只多一次绘制。

> **底色适配**：浅色端四档在 `surface.tint`（#D9E9F3）上依次 1.26 / 1.58 / 3.84 / 6.79 —— 亮档靠首字对比度承担可读性，不靠与底的分界；深色端依次 7.44 / 6.00 / 3.80 / **2.27**，所以深色端 **tone-4 不放在 `surface.tint` 上**（其余三档可用）。头像的实际落脚点是 `bg.canvas` 与 `surface.card-solid`，`tint` 只出现在"选中行"这类容器里。

### 1.3 分配规则（同一个人在任何页面配色一致）

**唯一实现**：

```text
toneIndex = FNV1a32(memberID) mod 4      // 0…3 → tone-1 … tone-4
FNV1a32: h = 0x811C9DC5
         for each byte b of UTF-8(memberID):
             h = (h XOR b) * 0x01000193   (32-bit wrap)
```

设计要求（实现侧逐条满足）：

| # | 要求 | 为什么 |
| --- | --- | --- |
| 1 | 输入是**成员 ID**（稳定标识），不是显示名 | 改名不能换色 |
| 2 | 纯函数、无状态、无随机 | 冷启动 / 换机 / 换页面必须同色 |
| 3 | 按 UTF-8 逐字节 | 两端同算法才能同色 |
| 4 | `mod 4` 直接出档，不再二次映射 | 少一层映射 = 少一处两端漂移 |
| 5 | **允许撞色** | 四个人撞到一档是允许的；区分身份靠名字与位置，不靠保证四色唯一 |

**取样结果**（给两端对拍 / 单测 fixture）：

| memberID | FNV-1a | mod 4 | tone |
| --- | --- | --- | --- |
| `u_1001` | 1050025199 | 3 | `tone-4` |
| `u_1002` | 1066802818 | 2 | `tone-3` |
| `u_1003` | 1083580437 | 1 | `tone-2` |
| `u_1004` | 966137104 | 0 | `tone-1` |
| `u_1005` | 982914723 | 3 | `tone-4` |

> `u_1001` 与 `u_1005` **撞色**（都是 tone-4），这是预期行为。写进文档是为了避免实现侧把撞色当算法错误。

### 1.4 照片形态

**解剖**：圆形照片 + **2pt 描边**（`size.avatar.ring`）。描边色 = **宿主底色**，使圆形照片与背景分开。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 裁切 | `Circle()` / `CircleShape` | 与文字形态同形 |
| 描边 | **2pt**（`size.avatar.ring`） | 与在线点描边同宽；**不新增色槽** |
| 裁切重心 | 默认居中 | 人脸偏置由调用方裁图（焦点参数见 §1.6-Q1） |
| 加载完成 | **160ms 淡入**（`motion.duration.fast`） | 设计 12 §9；不用缩放 |
| 加载中 | **不占位、不骨架** | 头像太小，骨架比照片本身更显眼 |
| 失败 / 空 | **退回文字形态** | 破图是零容忍项 |

**回退链**（硬规则）：

```text
有照片且已就绪 → 照片
否则 有文字     → 文字（tone 底 + ink 首字）
否则 有图标     → person 图标（surface.tint 底 + text.on-soft）
```

### 1.5 深色 / 停用 / 在线

| 情形 | 视觉 | 依据 |
| --- | --- | --- |
| 深色外观 | 用 `member.dark` 四色 | §1.2 |
| 已停用成员 | 整体 **50% + 去饱和** | 设计 12 §5（现行实现，不改） |
| 在线 | 右下 10×10 点 + **2pt 描边**，描边色 = 宿主底色 | 设计 12 §4 |
| 离线 | **不显示灰点** | 设计 12 §5 |

> **与现状的一处差异**：现行实现把在线点描边写死为 `surfaceCardSolid`。放在画布（`bg.canvas`）上时描边比宿主更亮，像「底下一圈白边」。本版要求描边色**由宿主传入**（默认 `surface.card-solid`，画布场景传 `bg.canvas`）。

### 1.6 未决项（需拍板，不阻塞实现）

| # | 项 | 建议 | 影响 |
| --- | --- | --- | --- |
| A11-Q1 | 是否要照片焦点参数（`unitPoint`） | **建议要**，默认 `(0.5, 0.5)`。人脸偏置是真实需求，不加参数就只能在调用点裁图 | 带默认值参数 = 源码兼容但破符号快照连续性 |

## 2. A-13 · `WDCard` 的 `media` 变体

### 2.1 结论先行

| # | 问题 | 结论 |
| --- | --- | --- |
| **C1** | 图片宽高比？ | **16:9（1.78）**，令牌 `size.card-media.aspect-ratio` |
| **C2** | 图片通栏还是内缩？ | **通栏**：左右与上边**贴到卡片边缘**，不叠 16 内边距 |
| **C3** | 那卡片内边距还是 16 吗？ | **是**，但**只对文字区生效**；图片带是自己的盒子 |
| **C4** | 图片圆角 = 卡片圆角吗？ | 图片带**上边 = 卡片圆角 24**，**下边不圆**（被文字区接住） |
| **C5** | 最窄多窄就不该用 `media`？ | 图片带高低于 **96**（`size.card-media.min-height`）时按 96 渲染、图片居中裁切；即卡片宽 < **171** 时不建议用 `media` |
| **C6** | 失败态？ | **灰底占位块**（`surface.card-sunken`），**不出破图、不出图标、不留白**；就绪后 160ms 淡入 |
| **C7** | 槽位词表要加 `media` 吗？ | **不用。** 图片是**参数**（`WDCardMedia` 值），不是槽位；F-15 的 21 名不动 |

### 2.2 几何

| 项 | 值 | 令牌 |
| --- | --- | --- |
| 图片宽高比 | **1.78（16:9）** | `size.card-media.aspect-ratio` |
| 图片最小高 | **96** | `size.card-media.min-height` |
| 图片带圆角 | 上 24 / 下 0 | `radius.xl` |
| 图片带通栏 | 是（左右上贴边） | — |
| 文字区内边距 | **16**（`space.5`） | 不变 |
| 图片内边距 | **0** | 通栏才能与卡片同圆角 |
| 卡间距 | 12（`space.4`） | 不变 |
| 卡片圆角 | 24（`radius.xl`） | 不变 |

尺寸实算（卡片宽 → 图片带高）：

| 卡片宽 | 图片带高 |
| --- | --- |
| 343（iPhone 竖屏 − 左右 16） | **193** |
| 390 | 219 |
| 171 | **96**（触发最小高） |

**为什么不通栏 + 内缩圆角（画廊里那种画法）**：画廊示例画的是「图片内缩 16 + 内层圆角 8」。这在浏览器上没问题，在真实卡片上会把「一张图 + 一段字」读成两个并列的块 —— 用户看到的是「卡里塞了一张小图」，而不是「这张卡以图片开头」。通栏是**卡片级**视觉，内缩是**卡内嵌块**视觉（那是 `sunken` 的语义）。选通栏。

**为什么不用 4:3**：343 宽下 4:3 = 高 257，一张图占掉半屏。`media` 的用途是「给一段文字配个引子」，不是图片浏览。

### 2.3 状态

| 状态 | 视觉 |
| --- | --- |
| 图片就绪 | 铺满图片带（`scaledToFill` + 裁切） |
| 加载中 | 灰底 `surface.card-sunken`，**无骨架、无微光**（卡片不是列表加载态） |
| 失败 / 无图 | 同「加载中」灰底；**不出破图** |
| 加载完成 | **160ms 淡入**，不用缩放 |
| 可点卡按下 | 整卡亮度 **96%**（`state.pressed.brightness`），图片一起压暗 |
| 禁用 | 整体 **40%** |

### 2.4 文字压在图上（可选，不是默认）

图片带**默认不放文字**。确要放（如「精选」角标）时：

1. 文字下垫 **25% `surface.card-solid`** 的圆角底（`06-accessibility.md` §5.2 规则 5）；
2. 角标距图片带边缘 **12**（`space.4`），圆角 **8**（`radius.xs`）；
3. 角标文字用 `text.primary`，字号不超过 `caption1`（12）；
4. **不允许**把白字直接压在照片上 —— 最不利取色过不了 4.5:1。

### 2.5 无障碍

| 项 | 要求 |
| --- | --- |
| 图片语义 | **装饰**（`accessibilityHidden(true)`）：`media` 卡的图片是引子，信息在文字区 |
| 例外 | 图片本身是内容（如相册缩略）时由调用方给 `accessibilityLabel`，此时图片进树 |
| 静态卡 | 不进焦点序列，文字逐项朗读（与现行静态卡一致） |
| 可点卡 | 整卡朗读，图片仍隐藏（标题已表达内容） |
| 对比度 | 文字区对 `surface.card` ≥ 4.5:1（着色见表 §2.2）；图片带默认无字，不参与对比度 |

### 2.6 与现有实现的关系

- `WDCardStyle` 现有 4 个 case（`elevated / outlined / glass / sunken`）。**新增 `media` 会破穷尽 switch**，属**源级 breaking**（`F-20` / `contracts/README.md` §7）。
- 交付形态建议：`WDCardStyle.media`（新 case）+ 重载 `init(style:media:content:)` / `init(style:media:action:content:)`，其中 `media` 是 `WDCardMedia` 值（图片 / 失败标记 / 无障碍标签）。
- `media` 与 `glass` **互斥**（图片带不做模糊；`glass` 是浮在内容之上的卡）；与 `sunken` 也不组合（`sunken` 是卡内嵌块）。

## 3. A-14 · `WDToolbar` 长按提示

### 3.1 结论先行

| # | 问题 | 结论 |
| --- | --- | --- |
| **C1** | 长按多久算长按？ | **500ms**（`size.tooltip.press-duration`），与系统 `LongPressGesture` 默认一致 |
| **C2** | 长按抬手会误触发 action 吗？ | **不会** —— 达到阈值即**取消点击**（仲裁规则见 §3.3） |
| **C3** | 提示长什么样？ | 实底气泡：高 28、圆角 8、单行；底色 `surface.card-solid` + hairline + `elevation.2` |
| **C4** | 提示能替代无障碍标签吗？ | **不能。** 提示是补充；每个图标按钮仍有必填 `accessibilityLabel`（设计 35 §10） |
| **C5** | 长按提示是 iOS 惯例吗？ | **不是**（iOS 惯例是长按弹菜单）。本条**只在「工具条按钮含义模糊」时启用**，且**不做成系统菜单** —— 避免与 `.contextMenu` 抢手势 |
| **C6** | 读屏用户怎么得到同一信息？ | 读 `accessibilityLabel`（本来就有）；提示**不进无障碍树**，不重复播报 |

### 3.2 几何与样式

| 项 | 值 | 令牌 |
| --- | --- | --- |
| 长按阈值 | **500ms** | `size.tooltip.press-duration`（令牌存 ms；iOS 出口按秒 `0.500`、Android 按毫秒 `500`，与各自 `motion.duration` 口径一致） |
| 气泡高 | **28** | `size.tooltip.height` |
| 气泡最大宽 | **200** | `size.tooltip.max-width` |
| 距按钮热区上边 | **8** | `size.tooltip.offset` |
| 圆角 | **8**（`radius.xs`） | 小尺寸元素用最小档 |
| 背景 | **`surface.card-solid`**（浅色 #FFFFFF / 深色 #0C212D） | 实底，**不上玻璃**（玻璃不承载多层内容，`06` §5.2） |
| 描边 | `border.hairline` 1pt | 与浅色画布分开 |
| 阴影 | `elevation.2` | 浮层 |
| 文字 | `caption2`（11/13，`letterSpacing` 0），`text.primary`，单行 | — |
| 左右内距 | **8** | 28 = 6 + 16（caption1 行盒）+ 6 的垂直对称 |
| 水平对齐 | 按钮中心；越界时**平移进安全区**（内侧留 8），**不做箭头** | — |

**对比度实算**：`text.primary` 在 `surface.card-solid` 上 = 浅色 **17.57:1** / 深色 **14.38:1**。

> **为什么不做箭头**：按钮 36×36、气泡高 28；加箭头后总高变 36，正好等于按钮高，视觉上会与按钮粘连。无箭头 + 8pt 间距更干净，也少一处几何分叉。

### 3.3 手势仲裁（A-14 的核心，也是 B17 一直没做的原因）

B17 的顾虑是：`Button` 上叠 `onLongPressGesture` 时，长按抬手可能**同时**触发 action。可执行的仲裁规则：

| 阶段 | 行为 |
| --- | --- |
| 按下（0ms） | 按钮进入按下态（缩放 0.94 + `fill.pressed`），与原行为一致 |
| 按住到 **500ms** | **显示提示**；同时**取消按下态**（回默认视觉），并**吞掉本次点击** |
| 500ms 内抬手 | 普通点击：执行 `action`，**不显示提示** |
| 500ms 后抬手 | **不执行 `action`**；提示保持到抬手后 **160ms** 淡出 |
| 500ms 后滑出热区 | 提示消失，本次手势作废（不执行 action） |
| `isEnabled == false` | **不显示提示**（提示是「这个按钮是什么」，禁用按钮不该被探索式触发） |

实现侧两条硬要求：

1. **不能用 `.simultaneousGesture`** —— 它保证两个手势都收到事件，正是误触成因。
2. **按钮本体用 `Button` + 自定义 `PrimitiveButtonStyle`**：按下状态与长按计时由**同一个状态机**驱动，「抬手是否执行 action」只有一个判断点。

### 3.4 动效

| 过渡 | 规格 |
| --- | --- |
| 出现 | **120ms** 淡入 + 上移 4pt，`easeOut`（不用 `motion.spring`：小元素弹一下太抢） |
| 消失 | **160ms** 淡出（`motion.duration.fast`） |
| 减弱动态 | 只淡入淡出，无位移（`06-accessibility.md` §6） |

> 120ms 不在 `motion.duration` 档位内（100 / 160 / 240 / 340 / 500）。这是**新增值**，见 §4.2-Q2；默认执行项 = 120ms。

### 3.5 文案

| 项 | 规则 |
| --- | --- |
| 字数上限 | **6 个汉字**（`07-content.md` §4 的按钮档 2–6） |
| 内容 | 与 `accessibilityLabel` **同源**，不另写一套 |
| 标点 | 不加句号、不加省略号 |
| 禁止 | 放解释性长句（「点击此按钮可以把当前任务标记为已完成」）—— 那是帮助文档，不是提示 |

### 3.6 无障碍

| 项 | 要求 |
| --- | --- |
| 提示本身 | `accessibilityHidden(true)`，**不进无障碍树** |
| 为什么 | 提示是视觉补充；读屏用户从 `accessibilityLabel` 已得到同样的词 |
| 重复播报 | 不允许（会打断用户正在读的内容） |
| 长按作为唯一入口 | **不允许** —— 长按是辅助路径，功能必须在点击路径上可达 |
