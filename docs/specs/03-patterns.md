# 场景模式（配方 R1–R5 + 组件 37）

这一层服务的是"多人协作的家庭工具"这个具体场景。但它和上面两层**性质不同**，写法也不同。

← [返回规格索引](README.md)｜配方可视化：[场景配方画廊](../../design/gallery/wisdom-patterns.html)（待补）

---

## 为什么这一层是"配方"而不是"组件"

7 个场景模式里，只有 `AssigneePicker` 是真正独立的控件，其余 6 个都是**用已有组件拼出来的固定组合**。

| 名称 | 实际是什么 |
| --- | --- |
| TaskRow | `WDListRow` + `WDCheckbox` + `WDAvatar` + `WDChip` 的组合 |
| SharedBadge | `WDBadge` 的一个预设 |
| StreakRing | `WDProgressRing` 的一个变体 |
| ReminderChip | `WDChip` + `WDPicker` 的组合 |
| FamilySpaceCard | `WDCard` + `WDAvatarStack` + `WDListRow` 的组合 |
| ~~MemberAvatarStack~~ | **已由组件 13 `WDAvatarStack` 覆盖，本条删除** |
| AssigneePicker | 头像横排 + 选择态，独立控件 → **组件 37** |

把产品语义塞进组件库有两个具体代价：**库和产品耦合**（别的 App 引入 WisdomUI 时 `FamilySpaceCard` 是废物），
以及**边界不断外扩**（"任务行"会长出子任务、批量选择，一路变成迷你应用）。

所以这一层按**配方**记录：写清楚用哪几个组件拼、数据怎么映射、什么时候成立。改配方没有向后兼容负担。

### 什么时候把配方提升为组件

三条同时满足才提升：

1. 在**两个以上**不同页面或项目里重复出现，且每次拼法几乎一样
2. 有自己的内部状态机（不只是把 props 透传）
3. 能起一个**不依赖产品语义**的名字（`AssigneePicker` 可以，`FamilySpaceCard` 不行）

### 配方怎么写

配方不用组件的 12 节模板，用下面 8 节。差别最大的是第 7 节——

**组件验收是逐条对尺寸、状态、无障碍；配方验收是拿去撞边界数据。**

| # | 章节 |
| --- | --- |
| 1 | 用途与适用场景 |
| 2 | 组成：用哪几个组件，各自承担什么 |
| 3 | 数据契约：需要哪些字段 |
| 4 | 状态映射：数据状态 → 视觉状态 |
| 5 | 布局与密度 |
| 6 | 交互与跳转 |
| 7 | **边界数据验收** |
| 8 | 什么时候提升为组件 |

# R1 · TaskRow 任务行

### 1. 用途与适用场景

列表里的一条任务。**用**：今日待办、本周家务、成员任务视图。
**不用**：任务详情（用整页）；已完成任务的归档视图（改用只读清单）。

### 2. 组成

| 位置 | 组件 | 承担 |
| --- | --- | --- |
| 容器 | `WDListRow`（双行 60） | 行高、分隔线、按下反馈、左滑删除 |
| 前导 | `WDCheckbox`（26） | 完成状态、点击切换 |
| 文本区 | 标题 `type.subheadline` + 副标题 `type.caption1` | 任务名、补充信息 |
| 尾部 | `WDChip` 或 `WDAvatar` / `WDAvatarStack` | 时间、负责人，**最多一个** |

### 3. 数据契约

```ts
type TaskRow = {
  id: string
  title: string            // 必填
  done: boolean            // 必填
  assignee?: Member        // 负责人，缺省表示"未指派"
  dueAt?: Date             // 截止时间，缺省表示无期限
  sharedWith?: Member[]    // 共享范围，缺省表示仅自己
}
```

### 4. 状态映射

| 数据 | 视觉 |
| --- | --- |
| `done = true` | 复选框选中；标题加删除线并降到 `text.tertiary`；副标题保持 |
| `dueAt` 已过 且未完成 | 尾部 Chip 用 `status.danger` + 实心禁止图标，文案"已逾期" |
| `dueAt` 在今天内 | 尾部 Chip 用 `status.warning`，显示时间点"18:00" |
| `dueAt` 明天及以后 | 尾部 Chip 用 `text.secondary`，显示"明天 / 周六" |
| `assignee` 存在 | 尾部显示该成员头像 |
| `sharedWith.length > 1` | 尾部改用 `WDAvatarStack` |
| `assignee` 与 `sharedWith` 都缺省 | 尾部不显示任何元素，**不留空位** |

优先级：逾期 > 时间 > 负责人。尾部只能放一个，冲突时按此顺序取舍。

### 5. 布局与密度

- 行高 60（双行）；标题与副标题各一行，都截断不换行
- 前导与文本区间距 `space.4`（12）；文本区与尾部间距 `space.3`（8）
- 一组任务之间用 1pt 分隔线，首行不画线
- 卡片内最多 5 行，超过时**不折叠**，改为进入"全部任务"页

### 6. 交互与跳转

| 操作 | 结果 |
| --- | --- |
| 点击整行 | 切换完成状态（不做成进入详情） |
| 点击尾部头像 | 打开该成员资料 |
| 长按 | 进入多选 |
| 左滑 | 露出删除，规则同组件 18 |
| 点击标题文字 | 同点击整行 |

进入详情的入口放在**尾部箭头**，与"整行切换完成"分开——这两件事不能共用一个点击区。

### 7. 边界数据验收

| 输入 | 期望 |
| --- | --- |
| 标题 40 个汉字 | 单行截断加省略号，行高不变，不换行 |
| 标题为空字符串 | 显示"未命名任务"，不用空白行 |
| 副标题 60 个汉字 | 单行截断 |
| 8 个共享成员 | 头像堆叠显示 4 个 + "+4" |
| 无截止时间 | 不显示时间芯片，尾部只剩一个头像 |
| 一屏 8 条全部逾期 | 8 个柔和红芯片并列仍可读，不刺眼 |
| 20 条已完成任务 | 删除线不影响副标题可读性 |
| 同一任务既是"已逾期"又有负责人 | 尾部显示逾期芯片，头像让位 |

### 8. 提升为组件

暂不提升。若"任务行"在其他项目里也按同一拼法出现，且需要内置子任务展开、重复规则等内部状态，
再考虑提为 `WDTaskRow`。

# R2 · SharedBadge 共享状态标记

### 1. 用途与适用场景

说明"这条内容谁能看到"。**用**：任务、日程、清单的头部。
**不用**：需要用户在这里修改共享范围（那是操作，用 `WDListRow` 或 `WDPicker`）。

### 2. 组成

`WDBadge`（`surface` 底 + 图标 + 文案）。三种形态：

| 形态 | 图标 | 文案 |
| --- | --- | --- |
| 全家共享 | `users` | 共享给全家 |
| 指定成员 | 成员头像 | 妈妈、爸爸 |
| 仅自己 | `lock` | 仅自己 |

### 3. 数据契约

```ts
type Sharing = {
  scope: 'family' | 'members' | 'private'
  members?: Member[]   // scope = 'members' 时有值
}
```

### 4. 状态映射

| 数据 | 视觉 |
| --- | --- |
| `scope = 'family'` | `users` 图标 + "共享给全家" |
| `scope = 'members'` 且人数 ≤ 2 | 成员头像（最多 2 个）+ 名字 |
| `scope = 'members'` 且人数 ≥ 3 | 改用"共享给 N 人"，不逐个列名字 |
| `scope = 'private'` | `lock` 图标 + "仅自己" |

### 5. 布局与密度

徽标高 24，图标 15，与相邻元素间距 `space.2`（4）；一行内不超过 2 个。

### 6. 交互与跳转

默认不可点。需要修改共享范围时，由外层提供一个独立入口（`WDListRow` 或 `WDChip out`）。

### 7. 边界数据验收

| 输入 | 期望 |
| --- | --- |
| 成员全部退出，只剩创建者 | 显示"仅自己"，不显示"全家 0 人" |
| 成员 10 人 | 显示"共享给 10 人"，不逐个列 |
| 成员名字 4 个字 | 徽标宽度自适应，不截断容器 |
| 成员已停用 | 不出现该成员 |
| 与"已逾期"徽标同排 | 两个都放得下就都显示；放不下时**保留状态类徽标，省略共享标记**——状态会变化，共享范围不会 |

### 8. 提升为组件

暂不提升。这是 `WDBadge` 的预设用法，没有独立状态机。

# R3 · StreakRing 连续完成环

### 1. 用途与适用场景

激励性指标：连续多少天完成全部任务。**用**：家庭首页、成员资料。
**不用**：任务进度（用 `WDProgressRing` 原样）；用来排名或比较成员（会造成压力，与"温和"基调冲突）。

### 2. 组成

`WDProgressRing`（直径 60）+ 环内数字（`type.title2` 等宽）+ 环下标签（`type.caption1`）。

### 3. 数据契约

```ts
type Streak = {
  days: number      // 连续天数，0 表示今天还没完成
  target?: number   // 目标天数，有值时环按 days/target 填充
}
```

### 4. 状态映射

| 数据 | 视觉 |
| --- | --- |
| `days = 0` | 环空（仅轨道），环内显示"—"，标签"今天开始" |
| `1 ≤ days < 7` | 环按 `days/7` 填充，环内显示天数，标签"连续天数" |
| `days ≥ 7` | 环色转 `status.success`，标签"连续 N 天" |
| 有 `target` | 环按 `days/target` 填充，达到后转为成功色 |

### 5. 布局与密度

环 60，环内数字 ≤ 3 个字符（两位数 + "天"），环下标签一行 ≤ 6 个汉字。
与相邻内容间距 `space.5`（16）。一屏最多一个。

### 6. 交互与跳转

不可交互。点击不展开历史——**不要做成"点开看打卡日历"**，那会把激励变成考核。

### 7. 边界数据验收

| 输入 | 期望 |
| --- | --- |
| `days = 0` | 显示"今天开始"，不显示"连续 0 天"，也不用灰色或断掉的环 |
| `days = 365` | 环填满，数字显示"365"，不溢出环内 |
| 断签后首次打开 | 归零到 0，**不做惩罚式提示**（不用"你断了"这类文案） |
| 环色与背景 | 深色外观下成功色仍可分辨（对比度 ≥ 3:1） |

### 8. 提升为组件

暂不提升。若将来需要"周目标 / 月目标"等更多模式，再考虑抽出 `WDStreakRing`。

# R4 · ReminderChip 提醒时间胶囊

### 1. 用途与适用场景

任务行或详情里显示与设置提醒时间。**用**：任务、日程。
**不用**：截止日期本身（那是 `dueAt`，用 `WDDatePicker`）；重复规则（用 `WDListRow` + `WDPicker`）。

### 2. 组成

`WDChip`（`out` 变体 + `bell` 图标）作为触发入口，点击后弹 `WDPicker` 菜单。

### 3. 数据契约

```ts
type Reminder = {
  remindAt?: Date
  repeat?: 'none' | 'daily' | 'weekly'
}
```

### 4. 状态映射

| 数据 | 视觉 | 文案 |
| --- | --- | --- |
| 无提醒 | 描边胶囊，`text.secondary` | "添加提醒" |
| 有提醒，今天 | `fill.field` 底 | "18:00" |
| 有提醒，其他日期 | `fill.field` 底 | "明天 09:00" |
| 重复提醒 | `fill.field` 底 | "每天 18:00" |
| 提醒时间已过且任务未完成 | `status-soft.warning` 底 | "已过时" |

### 5. 布局与密度

胶囊高 32；与相邻元素间距 `space.3`（8）；一行最多两个胶囊。

### 6. 交互与跳转

| 操作 | 结果 |
| --- | --- |
| 点击 | 弹出 `WDPicker` 菜单：今天晚些时候 / 明天上午 / 自定义 / 不提醒 |
| 选择"自定义" | 打开 `WDDatePicker` |
| 选择"不提醒" | 清空，胶囊回到"添加提醒" |

### 7. 边界数据验收

| 输入 | 期望 |
| --- | --- |
| 提醒时间刚过 1 分钟 | 显示"已过时"，不自动清空——用户需要知道它没响 |
| 跨时区旅行后打开 | 按**本地时间**重新计算显示，不显示原始时区的时间 |
| 重复提醒 + 具体时间 | 显示"每天 18:00"，不显示第一次的具体日期 |
| 提醒时间早于截止时间 | 正常，不提示——两者本来就可以不同 |
| 通知权限被拒 | 胶囊仍可设置，但保存后弹 `WDBanner` 说明不会收到通知 |

### 8. 提升为组件

暂不提升。这是 `WDChip` + `WDPicker` 的组合，没有独立状态机。

# R5 · FamilySpaceCard 家庭空间入口卡

### 1. 用途与适用场景

首页上进入某个家庭空间的入口。**用**：多家庭场景的首页、家庭切换。
**不用**：单个家庭的产品（那就没有"入口"的概念，直接展示内容）；成员管理页。

### 2. 组成

| 位置 | 组件 | 承担 |
| --- | --- | --- |
| 容器 | `WDCard`（`elevated` 或 `glass`） | 边界、投影、整卡可点 |
| 头部 | 家庭名（`type.headline`）+ `WDAvatarStack` | 谁在这个家庭里 |
| 中部 | 一行概览文案（`type.footnote`） | "今天完成 3 / 5" |
| 底部 | `WDProgressBar`（分段） | 今日完成度 |

### 3. 数据契约

```ts
type FamilySpace = {
  id: string
  name: string
  members: Member[]
  todayDone: number
  todayTotal: number
  uncheckedCount: number   // 未完成的总数，含历史遗留
}
```

### 4. 状态映射

| 数据 | 视觉 |
| --- | --- |
| `todayTotal = 0` | 进度条隐藏，概览文案改为"今天还没有任务" |
| `todayDone = todayTotal` 且 > 0 | 进度条满格并转 `status.success`，文案"今天全部完成" |
| `uncheckedCount > 0` | 概览文案补一句"另有 N 项未完成" |
| `members.length = 1` | 不显示头像堆叠，改为"邀请家人一起用" |

### 5. 布局与密度

卡片内边距 `space.5`（16）；头部与中部间距 `space.4`（12）；中部与进度条间距 `space.3`（8）。
卡间距 `space.4`（12）。一屏最多 4 张，超过改为列表。

### 6. 交互与跳转

整卡可点 → 进入该家庭空间。**不给卡片加箭头**（整卡可点时箭头是冗余的），
但按下时整卡降到 96% 亮度。

### 7. 边界数据验收

| 输入 | 期望 |
| --- | --- |
| 家庭名 20 个汉字 | 单行截断，头像堆叠不被挤出卡片 |
| 成员 10 人 | 堆叠显示 4 个 + "+6" |
| 成员 1 人 | 显示"邀请家人一起用"，不显示 1 个孤立头像 |
| `todayTotal = 0` | 不显示进度条，不显示"0 / 0" |
| 未完成 200 项 | 显示"另有 200 项"，不换行 |
| 4 张卡片同屏 | 每张高度一致，不因文案长短参差 |

### 8. 提升为组件

**不提升**。它带着"家庭空间"这个产品概念，进库会让库和这一个产品绑死。
如果将来出现第二个产品也用同样的"空间入口卡"，再考虑抽出中性的 `WDOverviewCard`。

# 37 · AssigneePicker

**视觉参考**：场景配方画廊（待补）｜ **优先级** P1

这是本层唯一的正式组件——有独立状态机，且名称不依赖产品语义。

### 1. 用途

在一组人里指派负责人。

- **用**：任务指派、日程参与人、清单归属
- **不要用**：选择对象超过 20 人（用带搜索的 `WDBottomSheet`）；选择非人物实体（用 `WDPicker`）

### 2. 解剖

头像横排 + 选中外环 + 可选"未指派"项 + 可选溢出项。

| 段 | 说明 |
| --- | --- |
| 头像 | `WDAvatar`（40），居中 |
| 选中外环 | 头像外描 2pt `text.brand`，与外径留 4 间隙 |
| 名字 | 可选，`type.caption1`，≤ 4 个汉字，居中 |
| 未指派项 | 虚线圈 + `user-x` 图标，语义是"暂时不指派" |
| 溢出项 | 第 6 个之后显示 `+n`，点击展开完整列表 |

### 3. 尺寸

| 项 | 值 |
| --- | --- |
| 头像 | 40 |
| 头像间距 | `space.4`（12） |
| 选中外环 | 2pt 描边 + 4 间隙（外径 52） |
| 名字与头像间距 | `space.2`（4） |
| 横向内边距 | `space.5`（16） |
| 最多直接显示 | 6 个（含"未指派"） |

### 4. 变体

| 变体 | 说明 |
| --- | --- |
| 单选（默认） | 选中一个，再点另一个则切换 |
| 多选 | 可选中多个，用于"参与人" |
| 带未指派 | 首位固定为"未指派" |
| 紧凑 | 头像 32，不显示名字，用于列表行内 |

### 5. 状态

| 状态 | 视觉 | 动效 |
| --- | --- | --- |
| 未选 | 头像无变化 | — |
| 选中 | 头像缩放 1.05，外描 2pt 品牌色环 | 200ms `motion.spring.bouncy`，环 160ms 淡入 |
| 按下 | 头像缩放 0.94 | 100ms |
| 禁用成员（已离开家庭） | 头像 40% 并去饱和，**仍可见但不可选** | 无 |
| 整体禁用 | 全部 40% | 无 |

### 6. 布局

- 横向排列，可横向滚动；滚动条不显示
- 当前选中项**始终保持在可视区内**（初始渲染时滚到该项）
- 组上方有标签（"指派给"），`type.footnote`，色 `text.secondary`
- 与下方内容间距 `space.5`（16）

### 7. 内容

- 名字 ≤ 4 个汉字，超出截断
- 没有名字的成员只显示头像，不显示占位文字
- 成员按"最近协作过"排序，不按字母——家庭场景里最近的人最可能是要选的人

### 8. 交互

| 操作 | 结果 |
| --- | --- |
| 点击头像 | 切换选中 |
| 点击"未指派" | 清空选择 |
| 横向拖动 | 滚动，不触发放大 |
| 长按头像 | 显示成员资料浮层 |
| 点击溢出项 `+n` | 展开完整成员列表（`WDBottomSheet`） |

### 9. 动效

选中 200ms `motion.spring.bouncy`（缩放 1.05 后回弹到 1），外环 160ms 淡入；
横向滚动到选中项时用 240ms `motion.spring.gentle`。

### 10. 无障碍

- 整组用 `radiogroup`（单选）或 `group`（多选）包裹，并给出组标签"指派给"
- 每项朗读"妈妈，已选中，单选按钮，第 2 项，共 4 项"
- 禁用的成员朗读"小李，已离开，不可选"
- 头像的首字标记为装饰，不朗读
- 触控热区 ≥ 44×44（头像视觉 40，热区补到 44）

### 11. 平台差异

iOS 用 `ScrollView(.horizontal)` + `HStack`；
Android 用 `LazyRow`，注意 `LazyRow` 的初始滚动位置用 `rememberLazyListState(initialFirstVisibleItemIndex:)`。
两端的横向滚动都要禁用过度回弹，避免和页面纵向滚动冲突。

### 12. 验收清单

- [ ] 头像 40、选中外环外径 52，误差 ≤ 1pt
- [ ] 最多直接显示 6 个（含"未指派"），超出显示 `+n`
- [ ] 初次渲染时选中项在可视区内
- [ ] 单选模式下点击已选项不取消
- [ ] 已离开家庭的成员可见但不可选，且有明确标注
- [ ] 成员按最近协作排序，不是字母序
- [ ] 头像视觉 40，热区 ≥ 44×44
- [ ] 读屏能读出"第 n 项，共 m 项"与选中状态
- [ ] 横向滚动与页面纵向滚动不冲突
