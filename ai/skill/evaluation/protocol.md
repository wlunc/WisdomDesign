# M5 固定 AI 任务对照评测协议（冻结稿）

> 状态：**待独立评审；未批准实施**。这是协议契约，不是评测报告。

## 1. 实验设计

固定三实验臂 A（现有方式）、B（精简规则文档）、C（生成 Skill）。控制变量见 `tasks.json#fixedConditions`：同模型、同参数、同需求、同宿主、同工程基线、同验证命令、同超时、同重试上限。

模型、宿主与工具版本在 M5 开跑前必须写入 run-manifest；三项任一变化都使该轮对照无效。参数默认值已冻结：temperature=0、topP=1、maxRepairRounds=2、生成超时 30 分钟/任务、平台验证超时 45 分钟/任务、失败重试 0 轮、seed 支持则固定否则记 null。

## 2. 指标口径

- 质量：首次编译、API 幻觉、设计违例、状态覆盖、平台矩阵、人工设计问题、最终人工修改行数。
- 修复：轮次与失败类型分布。
- 成本：端到端 Token = 入口规则 + 检索 + API/模板输入 + 业务输入 + 输出 + 错误反馈 + 修复轮次；另记缓存、工具调用、构建耗时、费用（可得时）与输出规模。
- 缓存命中与未命中分别计；不以 `SKILL.md` 缩短冒充总成本下降。
- 样本不足只写观察值，不给普遍百分比承诺。M4 后按基线设置回归阈值。

## 3. 证据留存

每任务每臂保留：run-manifest、输入/输出、工具调用日志、Token/缓存、原生命令退出码与日志、快照/UI 结果、最终 diff、设计评审、失败台账。失败样本不得删除。

## 4. 责任边界

编排与报告由 QA/评测负责人承担；编译与快照/UI 证据由对应平台负责人提供；设计评分由非实现者独立完成；宿主加载由 QA 在干净环境验证。AI 评测会调用模型并产生成本，与只读 `check`/结构验证分离。

## 5. 当前未验证

本 M0 契约任务没有运行模型、没有生成页面、没有执行原生验证，也没有成本数据。所有结果字段在真实评测前必须为空或标 `not-executed`。
